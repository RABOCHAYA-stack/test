# Модус · Обратная связь и предложения сотрудников

Работающий MVP для хакатона ГК «Модус Трейд»: сотрудники сообщают о проблемах и
предлагают улучшения, система маршрутизирует обращения ответственным, фиксирует
статусы, решения и показывает аналитику.

**Стек:** Python 3.10+ (только стандартная библиотека), SQLite, HTML/CSS/JS без сборки.
Внешние сервисы и установка зависимостей не требуются.

---

## Быстрый запуск

### Windows

Дважды кликните `start.bat` или выполните в папке проекта:

```bat
py app.py
```

### macOS / Linux

```bash
python3 app.py
```

Откройте **http://127.0.0.1:8000**.

> Если `python` не найден, используйте `py app.py` (Windows) или `python3 app.py`.
> При необходимости задайте порт: `set PORT=8080` (Windows) / `PORT=8080 python3 app.py`.

## Что реализовано

**Обращения**
- создание с типом, категорией, приоритетом, описанием, ожидаемым решением;
- вложение до 2 МБ (PDF, DOC/DOCX, XLS/XLSX, PNG, JPG, TXT);
- анонимная подача (автор скрыт от руководителей, виден администратору);
- коды обращений `A-001`, `A-002`, …

**Маршрутизация и рассмотрение**
- автоназначение ответственного по категории;
- fallback: если ответственный не задан/деактивирован — назначение администратору,
  обращение не теряется;
- статусы: Новое → На рассмотрении → В работе → Ожидает уточнения → Реализовано /
  Отклонено → Закрыто;
- SLA по приоритету: высокий — 3 дня, средний — 7 дней, низкий — 14 дней;
- просрочка подсвечивается в ленте и аналитике;
- взятие в работу, переназначение, результат рассмотрения / мотивированный отказ;
- комментарии автора и ответственного, внутренние заметки;
- полная история событий: регистрация, маршрутизация, смены статусов, решения;
- первый ответ и дата закрытия фиксируются автоматически.

**Доступ**
- роли сотрудник / руководитель / администратор;
- автор видит свои обращения и результат; руководители — рабочие комментарии;
- внутренние комментарии скрыты от сотрудников;
- анонимность: автор скрыт в ленте, карточке и комментариях (кроме администратора).

**Аналитика**
- KPI: всего, в работе, просрочено, доля рассмотренных, средний первый ответ,
  среднее время до результата, реализовано/отклонено;
- распределение по статусам, типам, приоритетам и категориям;
- динамика создания по неделям;
- повторяющиеся проблемы (2+ проблемы в категории);
- список просроченных обращений;
- реализованные улучшения;
- экспорт CSV (Excel-совместимый, UTF-8 BOM, `;`).

**Администрирование**
- создание и редактирование категорий;
- назначение ответственного по категории;
- включение/отключение категории;
- понятное правило маршрутизации и fallback.

## Ограничения MVP

- один узел и SQLite: рассчитано на демонстрацию и пилот, не на промышленную нагрузку;
- нет email/Telegram-уведомлений — статус виден в ленте и карточке;
- нет автоматической эскалации просрочки: она подсвечивается, но не переназначается;
- SLA фиксированный, без календаря рабочих дней и пауз в «Ожидает уточнения»;
- интеграции с Битрикс24, 1С и SSO не реализованы — описан план (см. `CONCEPT.md`);
- файлы не проверяются антивирусом; для пилота используйте только доверенные данные;
- анонимность не защищает от косвенной деанонимизации по подразделению/вложениям;
- нет rate limiting и двухфакторной аутентификации;
- поиск простой (LIKE), без полнотекстового индекса;
- руководитель может взять любое обращение (в пилоте это ограничивается подразделением).

## Безопасность (что уже сделано)

- пароли: PBKDF2-HMAC-SHA256, 120 000 итераций, индивидуальная соль;
- сессии: случайный токен в HttpOnly/SameSite=Lax cookie, срок 12 часов, хранение
  в БД в виде SHA-256-хеша;
- проверка ролей и прав на сервере для каждого действия, а не только в интерфейсе;
- параметризованные SQL-запросы;
- защита от path traversal при выдаче статики и вложений;
- ограничение размера запроса (5 МБ) и вложений (2 МБ), белый список расширений;
- CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`;
- все пользовательские строки экранируются при выводе;
- синтетические данные, отсутствие реальных клиентских сведений.
